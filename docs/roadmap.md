# 尚未实现的部分

这里只记录当前仓库里没有的能力，不是排期。

## 业务

- 只有查询。没有创建、修改、取消订单，也没有真实支付。
- 数据写死在三个 Java Repository 的 `Map` 里，进程重启后仍是同一份 Mock，但不能新增订单。
- 没有用户、登录、权限或审计。
- 支付账号是掩码 Mock，不连接支付宝或微信支付。

## 页面

- 「项目」「模板」「文档」「社区」「历史」「设置」「帮助」是禁用按钮。
- 搜索框可以输入，没有搜索行为。`⌘K` 只是按键样式。
- 对话、主题和失败重试都在 React state 中。刷新页面后消失。
- 页面不会直接请求 `trade-service`。

## Agent 与接口

- 工具选择依赖模型遵守 system prompt 和工具说明。仓库没有真实模型评测。
- 没有会话记忆。每次 `POST /chat` 只发送当前这一句 `message`。
- `get_trade_flow` 和 `get_trade_account` 还没有像 `get_order` 那样区分超时、连接失败和 HTTP 500。
- Java 不接受 `1001` 或 `ord-1001` 作为订单号。这种整理只在 Python 工具中发生。
- 没有 RAG、MCP、消息队列、Redis 或 Docker 配置。根目录也没有可运行的统一编排文件。

## 测试

- 没有浏览器、Agent、真实模型和 Java 同时参与的端到端测试。
- 没有针对本机 HTTP 代理的测试。`httpx.get` 使用库的默认代理设置。
- 没有 GitHub Actions 或其他 CI 定义。
